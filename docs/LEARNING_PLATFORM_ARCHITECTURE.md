# 测试能力修炼场：学习平台架构

## 1. 平台定位

这是一个帮助学习者持续进步的测试学习平台，不是项目文件浏览器，也不是把本地知识库直接搬上网页的展示站。

课程以可迁移能力组织。真实项目用于提供案例、任务和证据，但不是课程存在的前提。没有本地项目的 AI 测试、性能测试等模块，仍可以依靠公认基础和实时官方技术建立完整学习路径。

## 2. 三层知识来源

### 公认基础知识

- 优先使用语言、框架和工具官方文档。
- 其次使用正式标准、规范和权威研究机构资料。
- 普通博客和二手文章只能作为发现线索，不能直接成为课程事实。
- 基础知识形成主线课程的稳定骨架。

### 实时技术雷达

- 跟踪官方发布说明、Changelog、PEP、标准修订和权威研究更新。
- 每条雷达信息记录来源、版本、发现时间和最近核对时间。
- 草案、实验性能力和短期热点只进入雷达，不直接进入主线课程。
- 破坏性变化和弃用优先更新已有课程；稳定且可迁移的新能力才考虑新增关卡。

### 本地项目实践

- 当前 Python 框架基础、UI 自动化、API 自动化有本地项目来源。
- Python 来源包括 Skill、校验器、Provider、Runner、生成器和工具脚本。
- UI 自动化来源包括 EWMS/MOM 的 UI 知识库、Locator、Page Object、Playwright 脚本和执行证据。
- API 自动化来源包括 EWMS/MOM 的声明式 YAML、Adapter、Provider、静态门禁、Mock、teardown 和报告。
- 本地路径只用于构建前抽取，不在部署网站中暴露凭证、Token、登录状态或业务敏感数据。

| 模块 | 公认基础 | 技术雷达 | 本地项目 |
| --- | --- | --- | --- |
| Python 框架基础 | 必须 | 必须 | 已有 |
| UI 自动化 | 必须 | 必须 | 已有 |

## 4. 插件注册模型

平台将来源和课程拆成两种注册对象：

- `SourceAdapter`：声明来源类型、权威方、入口、核对时间和可贡献的知识。
- `LearningModule`：声明课程名称、来源引用、关卡路线和更新规则。

新增模块优先增加注册配置，不修改通用页面；新增来源只需注册 SourceAdapter，再由模块引用。

注册表必须检查：

- 模块 ID 唯一。
- 引用的来源必须存在。
- 关卡 ID 稳定且可迁移。
- 前置依赖不存在循环。
- 来源具备核对时间。

## 5. 新知识如何进入课程

1. 从官方来源或本地项目发现变化。
2. 提取候选知识点并记录证据。
3. 与现有知识图谱对比。
4. 按以下规则处理：

| 变化类型 | 处理方式 |
| --- | --- |
| 缺失的公认基础 | 补入基础关或基础知识弹窗 |
| 稳定、可迁移的新能力 | 增加进阶主关卡 |
| 已有能力的新难度 | 增加挑战关或支线任务 |
| 已有能力的新项目示例 | 更新案例和练习 |
| 尚未稳定的新技术 | 保留在技术雷达 |
| 纯业务字段或页面变化 | 不进入课程 |

新增主关卡必须具有：明确目标、前置知识、小白解释、实践任务和客观验证。

## 6. 学习进度与版本

- 进度使用 `moduleId.levelId` 保存，不依赖关卡顺序。
- 新增关卡不清空旧进度。
- 文案和案例更新不影响已通关状态。
- 验收标准发生实质变化时标记“建议复习”，不直接删除历史。
- 删除的关卡进入历史归档。
- 页面展示已掌握能力、待补前置知识、新增内容和需要复习的知识，而不只展示完成百分比。

## 7. 安全与内容边界

- 部署内容不得包含账号、密码、Token、Cookie、storage state、数据库连接或真实业务数据。
- 项目材料先经过白名单抽取和脱敏，再生成教学快照。
- 官方链接在页面展示最后核对日期。
- 技术雷达的自动发现不等于自动发布；进入课程前必须通过课程价值判断。
